# LiveTalking-560 实时交互数字人系统

本项目基于开源的 `lipku/LiveTalking` （https://github.com/cc072699/-livetalking.git）实时数字人引擎进行二次开发，由 **五六零人工智能（560 AI）** 团队深度定制与重构，旨在提供极致低延迟、高稳定性、内置企业专属知识库的音视频同步实时交互数字人解决方案。

---

## 🌟 560 二次开发优化特性

相较于原版，本项目在生产环境落地层面进行了多项核心重构与底层 Bug 修复：

1. **🎬 视频抖动深度消除**
   - 修复了原推理管线（Pacing）在静音与说话状态下的节拍器缩进 Bug，杜绝无限制帧堆积引发的画面卡顿与抖动。
   - 采用 OpenCV 像素级矩阵运算代替 PIL 进行字幕渲染，大幅度减少单帧合成耗时（从 30ms 降低至 1ms 左右），实现**流畅且极稳定的 25fps 视频推流**。
   
2. **🧠 专属企业知识库注入 (支持热更新)**
   - 在项目根目录引入 `prompt_config.yaml` 外部配置文件。
   - 内置“五六零人工智能”的公司定位、三大业务方向、核心产品、OPC 创业基地孵化、产学研合作等 16 项高频问答体系。
   - **热更新设计**：修改提示词或新增公司知识，**无需重启服务或修改代码，下一次提问自动生效**。

3. **🗣️ 预设 Ethan (男声) 默认音色 & 前端 Bug 修复**
   - 默认发音人改为男声 `Ethan`，并彻底重构了前端音色切换逻辑，修复了在“自由对话”和“文本驱动”中因硬编码导致无法自由切回女声 `Cherry` 的 Bug。

4. **🎤 ASR 本地语音识别环境修复**
   - 补齐了服务端 FunASR 缺少的 `torchaudio` 硬件驱动依赖，激活了本地 SenseVoice 语音识别引擎。
   - 现在在内网/弱网环境下，均可流畅使用**“自由对话”**与**“按住说话(PTT)”**功能。

5. **🔋 彻底消除内存溢出漏洞 (Memory Leak)**
   - 重构了 WebRTC 连接的生命周期。每当用户刷新页面或连接断开时，系统强制触发 `avatar.stop_render()` 以回收渲染线程及视频队列资源。
   - 解决了原版运行久了内存撑爆服务器的隐患，内存常驻占用稳定保持在健康水准（约 8.4 GB）。

## 🚦 快速开始

### 1. 配置提示词与知识库
项目根目录下的 `prompt_config.yaml` 可随时编辑修改，调整大模型的人设态度（当前已设定为**专业稳重**）与公司信息。

### 2. 启动服务
进入服务器项目路径，运行以下命令启动服务：
```bash
cd /home/wuhaitao/livetalkingtest/LiveTalking实时交互数字人
venv/bin/python app.py
```

### 3. 客户端访问
由于默认启用了安全 SSL，请使用以下方式在浏览器中打开（推荐使用 Chrome）：
**`https://<您的服务器IP>:8051`**
*(首次访问若提示证书安全风险，选择“高级” -> “继续前往”即可)*

## 📂 核心代码模块结构

- `app.py`：数字人主服务启动入口。
- `llm.py`：大模型对接处理，已集成外部知识库 `prompt_config.yaml` 动态读取。
- `prompt_config.yaml`：大模型角色扮演与公司专属知识库配置文件。
- `avatars/base_avatar.py`：数字人引擎基类，包含优化后的 OpenCV 字幕叠加与节拍推流控制。
- `server/session_manager.py`：已加入连接断开时自动关闭幽灵线程和释放队列资源的垃圾回收机制。
- `web/index.html`：优化了音色下拉框布局与逻辑的客户端网页。
